# Untitled — Dialog specification

Read the [theme foundations](../../themes/untitled.md), [component index](../../components.md), and [Base UI integration guidance](../../base-ui.md). This specification captures the current theme's authored edits and the preview's resolved values. Preserve these choices when implementing this component; do not replace them with generic library styling or approximate them from the overall theme.

## Anatomy

Dialog Root/Trigger, Portal with Backdrop and Popup, associated Title/Description, configured action, and an optional corner Close control.

## Layout and geometry

- Center a fixed popup in the viewport with a half-width/half-height translation. Its reference width is min(400px, viewport width minus XL spacing), height is content-driven, and maximum height is viewport height minus XL spacing with internal vertical scrolling. Arrange title, description, and actions vertically using the popup gap.
- Use a separate fixed full-viewport backdrop below the popup. The reference action footer aligns to the end, wraps when needed, uses XS spacing between actions, and has an XS top margin. A corner close control is S spacing from the top/right; reserve XL inline-end space in the title when it is present.
- Use zero native border width. Paint the resolved full edge with a zero-blur box shadow in its supplied inset/outer position, then retain the ordered elevation stack. Keep clipped inner bevels on a separate pointer-transparent overlay inset by the edge width; subtract that inset from each corner radius, clamped at zero. Neither edge width nor focus outline changes layout.

## States and behavior

- Use Large motion for popup opacity/scale and backdrop opacity. Keep the popup and backdrop mounted through their own exit lifecycle, then restore focus using the primitive. Preserve modal focus containment, accessible title/description, Escape, and the component’s distinct outside-dismissal policy.
- Apply the same theme, color mode, fonts, icon treatment, and motion variables inside the portal. For anchored popups, retain the primitive Positioner, collision handling, available-size variables, and transform origin; the anchor-to-popup offset is the popover part’s gap. Let the primitive own focus, dismissal, and exit mounting; do not copy editor popup pinning or simulated state.
- Keep the supplied keyboard-focus outline separate from surface shadows. Preserve selected/checked fill when focus coexists; an explicitly authored focus edge may replace only edge width/color, retaining the selected surface, edge placement, and elevation. Disabled styling takes precedence over interaction styling.

## Resolved specification

The JSON is design data, not a ready-made component. Each variant contains both modes, then parts and their supported states. `tokens` retains the named assignments; `style` contains the complete resolved appearance from the same resolver as the preview, including automatic foregrounds, per-corner radii, opacity, blur, focus treatment, and derived geometry. `css` contains the corresponding base CSS property values (camelCase property names; numeric dimensions are pixels except unitless properties).

Apply a part's relevant properties using its `properties` list and the anatomy/layout rules above. Text-only parts must not acquire a generic surface or padding simply because the base style object contains those fields. Keep themed properties linked to named tokens; use resolved values to reproduce and check derived treatments. `reference` identifies the immediate shared component and `source` its final owner, including the selected button variant. A button reference includes the referenced label's typography and foreground. Reuse that component so its refinements propagate consistently.

Compose shadow-based edges with elevation and separate inner bevels; native borders do not contribute to layout. Preserve the focus outline independently of checked, selected, and open fills. Reproduce the supported combined states described above rather than treating focus as an exclusive selection state. Structural widths can adapt to the receiving layout; authored spacing, typography, geometry, and surface treatments must remain intact.
