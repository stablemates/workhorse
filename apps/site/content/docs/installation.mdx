---
title: How do I install Workhorse?
description: Add the core package, install its PostgreSQL schema, and check compatibility before a process starts.
---

Workhorse needs an ESM Node.js application and a supported PostgreSQL server. Installation is a
deployment action because application processes must never change the schema implicitly.

## Add the package

Install `@workhorse/core` with the PostgreSQL client your application already uses.

```bash
pnpm add @workhorse/core pg
```

Add `@workhorse/drizzle`, a supported framework package, or `@workhorse/dashboard` only when that integration
belongs in the same process.

The `workhorse init` command can inspect an existing project. It writes a worker configuration and
prints a dashboard mount, but it leaves your routes and package manifest alone.

```bash
npx workhorse init
```

## Give Workhorse a database

Workhorse creates its objects inside the `workhorse` schema. The database role must be able to create
the schema, tables, indexes, partitions, and functions.

Your process supplies the connection through its normal configuration. The CLI accepts its database
flag and the documented Workhorse or application environment variables.

## Install the schema deliberately

Use the CLI in a deployment step when the target database is new.

```bash
npx workhorse schema install
npx workhorse schema status
```

You can perform the same step from deployment code with `installSchema`.

```ts
import { installSchema } from "@workhorse/core";
import { Pool } from "pg";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
await installSchema(pool);
await pool.end();
```

`installSchema` rejects a mixed or incompatible Workhorse schema. It will not guess how to migrate
durable state from another protocol version.

## Check before a runtime starts

Long-lived application and worker processes should call `assertSchemaCompatible`. That separates a
safe startup check from the destructive authority to install database objects.

```ts
import { assertSchemaCompatible } from "@workhorse/core";

await assertSchemaCompatible(pool);
```

Every published package is ESM and includes type declarations. JavaScript uses the same runtime API,
while TypeScript also checks payloads and configuration during development.
