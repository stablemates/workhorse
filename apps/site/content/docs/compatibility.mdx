---
title: Which runtimes does Workhorse support?
description: Understand the tested Node.js, PostgreSQL, module, package, and schema compatibility boundaries.
---

A runtime is supported when continuous integration runs the full suite against it. Workhorse may run
elsewhere, but untested versions do not carry the same correctness evidence.

## Check the current matrix

The exact Node.js and PostgreSQL majors change over time, so the
[compatibility matrix](https://github.com/stablemates/workhorse/blob/main/docs/compatibility.md) owns
those values.

`SUPPORTED_NODE_MAJORS` and `SUPPORTED_POSTGRES_MAJORS` expose the same release boundary to tooling.
`describePostgresSupport` explains whether a connected server is tested, merely newer, or refused.

```ts
import { readPostgresSupport } from "@workhorse/core";

const support = await readPostgresSupport(pool);
console.log(support);
```

Workhorse requires plain PostgreSQL with its default procedural language. It installs no optional
extension.

Published packages are ESM and include TypeScript declarations. JavaScript uses the same runtime,
while CommonJS loading is outside the supported package format.

## Match the schema exactly

The PostgreSQL schema is the durable protocol. An application runtime and installed schema must agree
exactly because workers can otherwise interpret lifecycle state differently.

Call `assertSchemaCompatible` during startup. A mismatch should fail the process before it claims or
changes work.

Schema installation is clean-install only. Workhorse does not provide an online migration path, so a
protocol change needs a separately designed drain and data transition.

The dashboard transport can change without a schema bump because it is private to matching package
versions. Use the public `Queue` read API for application integrations.

## Treat releases as one package set

Core and its integration packages release together. Keep their versions aligned so adapters,
dashboard contracts, and exported types describe the same source revision.

The [changelog](https://github.com/stablemates/workhorse/blob/main/CHANGELOG.md) records breaking
changes and the schema required by each release.

Support proves correctness under the tested matrix. It does not promise a throughput level for your
database, payloads, handlers, or deployment topology.
