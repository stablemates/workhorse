---
title: Where do I start with Workhorse operations?
description: Route each operational concern to the guide that owns its mechanism and evidence.
---

Workhorse separates process supervision from database maintenance. Start with the boundary you need
to change, because each guide keeps its own configuration and failure behavior.

## Process supervision

[Worker processes](/docs/worker-processes) owns startup, termination signals, drain behavior, probes,
and database pool ownership.

## Database maintenance

[Maintenance and retention](/docs/maintenance) owns promotion, recovery, partitions, cleanup,
retention policy, and the health signals that show lag.

## Fleet and job controls

[Workers](/docs/workers) owns local lifecycle controls and operator requests that stop workers from
asking for jobs.
[Cancellation](/docs/cancellation) owns durable requests to stop one job.

[Dashboard](/docs/dashboard) owns the authorization boundary for operator mutations, while
[Queries and timelines](/docs/queries) owns read-only inspection.

## Next

- [Maintenance and retention](/docs/maintenance) — keep PostgreSQL cleanup healthy
- [Compatibility](/docs/compatibility) — reject a mismatched runtime before startup
