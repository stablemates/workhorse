---
title: When is Workhorse the wrong fit?
description: Compare the current delivery, scheduling, orchestration, authorization, and migration boundaries with your requirements.
---

Workhorse fits PostgreSQL-backed applications that accept at-least-once handlers and a clean-install
schema. Choose another system when a missing capability is central to your workload.

## External effects are at least once

PostgreSQL cannot commit an HTTP call, email, or payment in the same transaction as job completion. A
worker can finish the effect and die before it records success.

Use provider idempotency keys, transactional inbox or outbox patterns, or compensation. Enqueue keys
prevent duplicate job identities, but they cannot make one accepted handler execute exactly once.

Redrive creates another at-least-once execution. Operator tooling must confirm that repeating the
effect is safe before it replays failures.

## Scheduling is durable rather than real time

Delayed jobs and durable waits store not-before boundaries. Promotion cadence, queue pause, worker
availability, and database downtime can delay the next claim.

Recurring schedules need a running worker with the matching namespace. Workhorse bounds catch-up
after downtime and does not provide a hard real-time scheduler.

## Stop is cooperative

Cancellation, deadlines, and execution timeouts abort a handler signal. JavaScript continues until
the handler observes that signal or loses its lease.

Process shutdown also drains rather than preempts handlers. If your application requires immediate
forced interruption, isolate that work in a process you can terminate and make its effects recoverable.

## Workhorse is a queue, not a workflow engine

Workhorse has FIFO queues, but no priorities, dependency graph, child-job runtime, or cross-queue
concurrency policy. Application code must model orchestration explicitly or use a workflow system.

Durable waits are time-based. They do not accept arbitrary signals or operator early wake commands.

## The host owns security and telemetry

The dashboard and mutation APIs provide attribution, not authentication, authorization, role-based
access, or tenant isolation. Every host must enforce its own operator boundary.

Workhorse exposes health and maintenance telemetry but no built-in metrics endpoint or tracing export.
Connect handler and process signals to your observability system.

## Schema evolution needs a deliberate migration

The current schema installs cleanly and requires an exact runtime match. Workhorse does not ship
online schema migration or compatibility write views between protocol versions.

This boundary matters most for long-lived production data. Plan the drain, cutover, and evidence
retention before adopting a release that changes the schema.
