---
title: Drizzle
description: Enqueue inside caller-owned Drizzle transactions with @workhorse/drizzle.
---

`@workhorse/drizzle` adapts node-postgres Drizzle databases and caller-owned transactions without
adding Drizzle to `@workhorse/core`.

```bash
pnpm add @workhorse/drizzle drizzle-orm pg
```

## Create the adapter

```ts
import { Pool } from "pg";
import { drizzle } from "drizzle-orm/node-postgres";
import { createDrizzleAdapter } from "@workhorse/drizzle";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
const db = drizzle({ client: pool });

const workhorse = createDrizzleAdapter(db, {
  defaultQueue: "default",
  // The adapter never closes caller-owned pools unless you ask it to.
  close: () => pool.end(),
});
```

`createDrizzleAdapter` returns a `WorkhorseAdapter`:

```ts
interface WorkhorseAdapter<TTransaction = Queryable> {
  readonly database: Queryable;
  readonly queue: Queue;
  forTransaction(transaction: TTransaction): Queue;
  createWorker(options?: WorkerOptions): Worker;
  close(): Promise<void>;
}
```

## Transactional enqueue

Call `forTransaction(tx)` inside `db.transaction(...)` so enqueue commits or rolls back with your
application writes.

```ts
await db.transaction(async (tx) => {
  await tx.insert(account).values({ id: accountId, email });
  await workhorse.forTransaction(tx).enqueue("account.created", { accountId });
});
```

If the transaction rolls back, the job never existed.

## Workers

```ts
const worker = workhorse.createWorker({ workerId: "worker-1", concurrency: 4 });
worker.handle("account.created", async (payload) => ({ ok: true }));
await worker.run();
```

## Lower-level helper

`drizzleQueryable(executor)` converts any Drizzle database or transaction into the core `Queryable`
protocol, if you want to construct a `Queue` yourself:

```ts
import { drizzleQueryable } from "@workhorse/drizzle";
import { Queue } from "@workhorse/core";

const queue = new Queue(drizzleQueryable(db), "billing");
```

## Errors

Database failures are rethrown as `DrizzleQueryError`:

```ts
import { DrizzleQueryError } from "@workhorse/drizzle";

try {
  await workhorse.queue.enqueue("email.send", payload);
} catch (error) {
  if (error instanceof DrizzleQueryError) {
    error.statement; // the SQL text Workhorse issued
    error.code; // PostgreSQL error code when available
    error.cause; // the original error
  }
  throw error;
}
```

Typed Workhorse errors such as `EnqueueIdempotencyConflictError` are still raised as themselves, so
your conflict handling keeps working through the adapter.

## Resource ownership

<Callout>
The adapter does not close caller-owned pools by default. Pass `close: () => pool.end()` (or
`() => db.$client.end()`) **only** when the adapter owns that pool. `adapter.close()` is idempotent.
</Callout>

## Schema installation

Drizzle does not manage the Workhorse schema. Install it explicitly:

```ts
import { installSchema } from "@workhorse/core";

await installSchema(workhorse.database);
```

Keep the Workhorse schema out of your Drizzle migration graph. It is versioned and clean-install only.
