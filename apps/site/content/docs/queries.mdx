---
title: How do I inspect jobs and timelines?
description: Read point state, bounded listings, lifecycle evidence, and queue health without widening dispatch indexes.
---

Operator reads use `job_query` and append-only history instead of scanning the live dispatch paths.
That separation keeps inspection cost from changing how workers find ready jobs.

## Read one known job

`Queue.getJob` joins immutable identity to its runtime or outcome row and returns a `JobSnapshot`.

```ts
const snapshot = await queue.getJob(jobId);

if (snapshot) {
  console.log(snapshot.state, snapshot.currentAttempt, snapshot.result);
}
```

The method returns `null` for an unknown or retired identity. Use it when existence matters because a
history query alone cannot distinguish those cases.

## List jobs with a bounded projection

`Queue.listJobs` filters by queue, type, state, tags, and creation time. It orders pages by immutable
creation keys and returns a signed cursor for the next call.

```ts
const page = await queue.listJobs({
  queue: "billing",
  states: ["active", "failed"],
  payload: {
    include: true,
    redactKeys: ["cardNumber", "accessToken"],
  },
});
```

Payload is omitted by default because operator lists rarely need it. When requested, PostgreSQL
applies bounded top-level redaction and a response ceiling, then marks each payload as included,
omitted, or too large.

A cursor belongs to the filters and payload projection that created it. Reusing it with a different
query fails instead of silently changing page membership.

Pages are weakly consistent across calls. New jobs and concurrent state changes can affect later
pages, so use `Queue.getJob` for authoritative point lookup.

## Reconstruct lifecycle evidence

`Queue.getJobTimeline` merges retained `job_event` and `attempt_history` rows into one newest-first
stream.

```ts
const timeline = await queue.getJobTimeline(jobId);

for (const entry of timeline.items) {
  console.log(entry.kind, entry.occurredAt);
}
```

History categories retire independently. A known job can therefore have a partial or empty timeline,
which is why timeline absence does not prove identity absence.

`Queue.getCheckpoint`, `listCheckpoints`, `getWait`, `listWaits`, and `getProgress` expose the other
durable projections without interpreting them as lifecycle state.

## Read queue health as an operational snapshot

`Queue.health` reports depth, lease expiry, overdue waits, deadline pressure, retention lag, relation
statistics, and PostgreSQL pressure.

The method assembles independent read-only queries, and PostgreSQL statistics may lag. Treat the
result as an operational signal rather than one transactionally consistent instant.

The `workhorse-health` CLI prints the same kind of snapshot for probes and scripts.
