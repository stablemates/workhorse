---
title: Which patterns should I copy first?
description: Start from verified examples for transactional acceptance, durable stages, and safe operator recovery.
---

The safest Workhorse patterns align one durable primitive with one failure boundary. These examples
use current exported methods and leave domain policy in application code.

## Accept work with business data

Use an adapter queue for the caller's transaction. If the callback rolls back, neither the account
nor its follow-up job survives.

```ts
await db.transaction(async (transaction) => {
  const account = await createAccount(transaction, input);

  await workhorse
    .forTransaction(transaction)
    .enqueue(
      "account.created",
      { accountId: account.id },
      { idempotency: { key: `account-created:${account.id}` } },
    );
});
```

The enqueue key protects a repeated application request. It does not protect external effects when
the accepted job runs again.

## Preserve completed handler stages

Wrap expensive or external stages in named checkpoints, and give the external provider its own
stable idempotency key.

```ts
worker.handle("order.fulfill", async (payload, context) => {
  const charge = await context.checkpoint("charge", () =>
    payments.charge(payload.orderId, {
      idempotencyKey: `charge:${payload.orderId}`,
    }),
  );

  const shipment = await context.checkpoint("shipment", () =>
    logistics.createShipment(payload.orderId, charge.id),
  );

  await context.sleepUntil("carrier-window", new Date(payload.carrierReadyAt));

  return context.checkpoint("tracking", () => logistics.readTracking(shipment.id));
});
```

When the wait ends, the handler starts from the top. Saved checkpoints return their values, while
the first boundary that has not completed performs its operation.

## Make long loops cancellation-aware

Check the signal before starting another unit and pass it into APIs that support cancellation.

```ts
worker.handle("export.build", async (payload, context) => {
  for (const part of payload.parts) {
    if (context.signal.aborted) throw context.signal.reason;

    await context.checkpoint(`upload:${part.id}`, () =>
      storage.upload(part, { signal: context.signal }),
    );
  }

  return { exportId: payload.exportId };
});
```

This stops new work promptly after cancellation. It cannot undo a completed upload, so each upload
still needs domain idempotency or compensation.

## Preview an incident redrive

Use the same filter and request for preview and execution. Reusing the request ID makes a repeated
operator command converge on existing targets.

```ts
const request = {
  requestedBy: actor.email,
  reason: "provider incident resolved",
  requestId: incident.id,
};

const preview = await queue.redriveMany(filter, request, { dryRun: true });

if (approve(preview)) {
  await queue.redriveMany(filter, request);
}
```

Authorize the actor before either call. Dry run proves eligibility, while your application remains
responsible for deciding whether replaying the effects is safe.
