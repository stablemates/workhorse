---
title: How do I run my first job?
description: Create a Queue, enqueue work, register a handler, and inspect the durable result.
---

A job needs a `Queue` to accept it and a `Worker` with a matching handler to run it. This example
keeps both in one file so the lifecycle stays visible.

## Create the queue

`Queue` accepts a `Queryable`, which a node-postgres `Pool` already implements.

```ts
import { Pool } from "pg";
import { Queue, Worker } from "@workhorse/core";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
const queue = new Queue(pool);
```

Install the schema before this process starts. Runtime code should check compatibility instead of
installing database objects.

## Register the handler

The string passed to `Worker.handle` must match the job type. The handler receives the payload and a
`HandlerContext`, and its JSON result becomes the immutable outcome.

```ts
const worker = new Worker(queue).handle("email.welcome", async (payload: { to: string }) => ({
  deliveredTo: payload.to,
}));
```

## Enqueue and run the job

`Queue.enqueue` returns the durable job ID. `Worker.runOnce` performs one claim pass, which makes it
useful in a small example or a test.

```ts
const jobId = await queue.enqueue("email.welcome", {
  to: "person@example.com",
});

await worker.runOnce();
console.log(await queue.getJob(jobId));
await pool.end();
```

Production workers normally call `Worker.run` and keep its promise until shutdown. A dedicated
worker process can then stop claims, drain active handlers, and close its own database pool.

If enqueue belongs to an application transaction, pass that transaction to `Queue.enqueue`. The job
then commits or rolls back with the surrounding business write.
