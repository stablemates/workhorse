---
title: How do I use Workhorse with Fastify?
description: Inject queue access into Fastify requests and bind workers to Fastify lifecycle hooks.
---

`@workhorse/fastify` joins a `WorkhorseAdapter` to one Fastify process. It exposes queue access as
`request.workhorse` and uses Fastify's lifecycle hooks for co-hosted workers.

```ts
import Fastify from "fastify";
import { FastifyWorkhorse, registerWorkhorse } from "@workhorse/fastify";

const workhorse = new FastifyWorkhorse(adapter);
const app = Fastify();
await registerWorkhorse(app, workhorse);

app.post("/jobs", async (request, response) => {
  const id = await request.workhorse.queue.enqueue("email.send", request.body);
  return response.send({ id });
});

await app.listen({ port });
process.once("SIGTERM", () => void app.close());
```

Dedicated worker processes remain the production default. If `FastifyWorkhorse` has worker
definitions, `onReady` starts them once, `preClose` stops new claims and drains handlers, and
`onClose` closes adapter-owned resources.

The dashboard has its own lifecycle. Register `@fastify/middie`, then mount
`dashboardNodeMiddleware` from `@workhorse/dashboard/server`; mounting needs a database connection
but no worker runtime.

Use `workhorse.contextFor(request)` for a caller-owned transaction. Fastify's global request type
cannot carry the adapter's transaction type, so this method restores the checked bridge.
