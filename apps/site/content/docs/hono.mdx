---
title: How do I use Workhorse with Hono?
description: Add typed queue access, coordinated lifecycle management, and an authorized dashboard mount.
---

`@workhorse/hono` joins a `WorkhorseAdapter` to one Hono process. It provides typed request context,
worker startup, ordered shutdown, and a dashboard mount.

## Create the runtime

Install the Hono integration with the server packages your application uses.

```bash
pnpm add @workhorse/hono hono @hono/node-server
```

`HonoWorkhorse` accepts an adapter from core or the Drizzle integration. Its worker definitions use
the same `WorkerOptions` and `Worker.handle` methods as a dedicated process.

```ts
import { HonoWorkhorse } from "@workhorse/hono";

const workhorse = new HonoWorkhorse(adapter, {
  workers: [
    {
      configure(worker) {
        worker.handle("email.send", sendEmail);
      },
    },
  ],
});
```

Co-hosting workers is useful for small deployments, but HTTP replicas then multiply job capacity.
Use a dedicated worker process when the two workloads need independent scaling or drains.

## Add typed queue access

`workhorse.middleware()` stores `queue` and `forTransaction` on `c.var.workhorse`.

```ts
const app = new Hono().use(workhorse.middleware()).post("/jobs", async (context) => {
  const id = await context.var.workhorse.queue.enqueue("email.send", await context.req.json());
  return context.json({ id });
});
```

Inside a database transaction, call `forTransaction(transaction)` before enqueue. That keeps the job
inside the caller's commit boundary.

## Coordinate startup and shutdown

`serveWithWorkhorse` starts the worker runtime and Hono server together. Its returned `shutdown`
method stops new connections, quiesces workers, drains requests, and closes adapter resources.

If server startup fails, the helper stops the runtime before it rethrows. After
`HonoWorkhorse.stop` closes owned resources, the instance cannot restart.

## Mount the dashboard behind authorization

`mountWorkhorseDashboard` maps the framework-neutral dashboard host onto a Hono path.

```ts
import { mountWorkhorseDashboard } from "@workhorse/hono";

mountWorkhorseDashboard(app, {
  database: adapter.database,
  path: "/workhorse",
  environment: "production",
  authorize: (request) => isOperator(request),
});
```

The mount owns only its configured path and falls through elsewhere. It needs a database connection,
not a worker runtime, because workers publish fleet state to PostgreSQL.

`authorize` must protect every HTML, asset, and RPC request. Workhorse records operator attribution
but provides no authentication or role model.
