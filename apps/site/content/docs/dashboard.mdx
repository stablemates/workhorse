---
title: How do I mount the operator dashboard?
description: Serve the packaged React interface from any host while keeping authorization and mutations under application control.
---

`@workhorse/dashboard` reads operator state from PostgreSQL and serves its interface through a
framework-neutral host. It does not need to run beside the workers it observes.

## What does the dashboard show?

The interface lists jobs, attempts, checkpoints, progress, schedules, queues, workers, failures, and
system health. It can also expose host-authorized controls for cancellation, run-now actions, queue
state, schedules, and requests that pause workers.

Every view comes from PostgreSQL read models. A dashboard process can therefore report workers from
separate machines without reading their process memory.

## Create the server host

`createDashboardHost` accepts a `Request` and returns a `Response` only when it owns the configured
path.

```ts
import { createDashboardHost } from "@workhorse/dashboard/server";

const host = createDashboardHost({
  path: "/workhorse",
  database: pool,
  environment: "production",
  authorize: (request) => isOperator(request),
});
```

Fetch-native frameworks call `host.handle(request)`. Connect-style frameworks wrap the same host
with `dashboardNodeMiddleware`, while Hono can use `mountWorkhorseDashboard`.

The host checks schema compatibility and refuses incompatible requests. It never installs or
migrates database objects.

## Treat authorization as a host responsibility

The `authorize` callback protects the interface, assets, and RPC methods. Workhorse has no built-in
authentication, role model, or tenant boundary.

Use `operator`, `queueController`, `taskController`, `workerController`, `scheduleController`, and
`settingsController` when mutations must pass through your own authorization and audit services.

`auditActor` and `requestedBy` provide attribution after authorization. They do not grant permission
by themselves.

The settings page keeps database policy separate from deployment configuration. It edits maintenance
and retention through `DashboardSettingsController`, previews destructive retention changes, and
shows process-owned worker values without offering runtime edits.

## Customize without forking the interface

Hosts can render `Dashboard` and `WorkhorseThemeProvider` directly, then connect them with
`createDashboardClient`. Import the packaged stylesheet so the component receives its expected
tokens and layout.

`configuredWorkers` can describe expected processes before they first register. `projectDurability`
can translate checkpoint evidence into domain-specific steps without changing stored queue data.

The standalone `workhorse dashboard` command is useful for a local console. Unless the operator
explicitly enables mutations, the command remains read-only. An authenticated embedded mount remains
the production choice.

## Read refreshes as bounded polling

The browser refreshes only the active page at the selected cadence. Job volume does not create extra
browser requests, and manual refresh remains available when polling is undesirable.

The dashboard is an operator view rather than a transactional snapshot. PostgreSQL statistics and
worker registry data can lag their underlying processes.
