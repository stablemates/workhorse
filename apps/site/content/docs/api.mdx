---
title: Where do I find the Workhorse API?
description: Use the exported surface to choose an entry point, then rely on the published declarations for exact signatures.
---

Most applications need `Queue`, `Worker`, and one schema check from `@workhorse/core`. The published
type declarations are authoritative for signatures because they ship with the implementation.

## Manage the schema

`installSchema` installs a clean schema during deployment. `readSchemaVersion` inspects an existing
database, while `assertSchemaCompatible` protects runtime startup.

`WORKHORSE_SCHEMA_VERSION`, `describePostgresSupport`, and the exported support constants let tooling
explain the runtime boundary without duplicating it.

## Accept and inspect jobs with `Queue`

`Queue.enqueue` and `enqueueMany` accept work. Queue controls include `pauseQueue`, `resumeQueue`,
`purgeQueue`, `promote`, and `runTaskNow`.

Operator reads include `getJob`, `listJobs`, `getJobTimeline`, `health`, `listWorkers`, and the durable
boundary readers.

Cancellation uses `cancel`. Failure recovery uses `listDeadLetters`, `redrive`, `redriveMany`, and
`getRedriveLineage`.

Schedule and policy methods include `syncSchedules`, `schedules`, `syncRetentionPolicy`,
`syncMaintenancePolicy`, and their corresponding readers.

Low-level protocol methods such as `claim`, `heartbeatStatus`, `complete`, `fail`, and
`acknowledgeCancel` exist for custom runtimes and tests. Ordinary applications should let `Worker`
drive them.

## Execute handlers with `Worker`

`Worker.handle` registers a `Handler`. `run` owns the continuous loop, while `runOnce` performs one
claim pass for tests and scripts.

`pause`, `resume`, `stop`, `runtimeState`, and `maintenanceTelemetry` expose local lifecycle state.
The worker ID is its lease-owner identity rather than a stable deployment name.

`HandlerContext` provides `job`, `signal`, `checkpoint`, `getCheckpoint`, `sleep`, `sleepUntil`,
`getWait`, `setProgress`, and `getProgress`.

## Build process and framework adapters

`createWorkhorseAdapter` gives database providers a stable `WorkhorseAdapter`. Dedicated processes use
`defineWorkerProcess`, `startWorkerProcess`, or `runWorkerProcess`.

`@workhorse/drizzle` exports `createDrizzleAdapter`, `drizzleQueryable`, and `DrizzleQueryError`.
`@workhorse/hono` exports `HonoWorkhorse`, `serveWithWorkhorse`, and `mountWorkhorseDashboard`.

`@workhorse/dashboard` exports the React surface, while `@workhorse/dashboard/server` exports the
host, Node middleware, read models, router, SQL adapter, and packaged asset helpers.

## Handle typed failures narrowly

Core exports distinct errors for enqueue and redrive conflicts. Other classes cover stale writes,
boundary conflicts, rate or count limits, cancellation, deadlines, timeouts, and test failpoints.

Catch the narrow class whose recovery your application understands, then rethrow unknown errors.
Avoid switching on message text because the classes and structured details are the stable contract.

The current declaration entry point is
[`src/index.ts`](https://github.com/stablemates/workhorse/blob/main/src/index.ts).
