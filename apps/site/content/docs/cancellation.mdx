---
title: How do I cancel a job?
description: Request a cooperative stop and let PostgreSQL preserve the winning terminal outcome.
---

JavaScript cannot be preempted safely, so Workhorse cancellation is cooperative. PostgreSQL can
finish work without an active owner immediately, but an active handler must observe its `AbortSignal`.

## Request cancellation

Call `Queue.cancel` after your application authorizes the actor.

```ts
const result = await queue.cancel(jobId, {
  requestedBy: actor.email,
  reason: "customer withdrew the order",
});
```

`requestedBy` and `reason` are audit attribution. Workhorse records them but does not decide whether
the actor had permission.

If the job is `ready`, `scheduled`, or in a durable wait, PostgreSQL writes the canceled outcome
immediately. A job that never started receives no invented attempt history.

If the job is `active`, PostgreSQL records one durable request. The worker receives that request from
`heartbeat_v2` and aborts the handler signal with `CancellationRequestedError`.

## Make the handler cooperate

Pass `context.signal` into APIs that accept an `AbortSignal`. Check it between units of work before
starting another external effect.

```ts
worker.handle("export.build", async (payload, context) => {
  for (const part of payload.parts) {
    if (context.signal.aborted) throw context.signal.reason;
    await uploadPart(part, { signal: context.signal });
  }

  return { exported: true };
});
```

Cancellation does not undo effects that already happened. Use compensation when the domain requires
reversal, and keep each effect safe for at-least-once execution.

If a handler ignores the signal, its lease eventually expires. Recovery sees the durable request and
materializes cancellation instead of creating another attempt.

## Which result wins a race?

Cancellation, completion, and failure lock the same runtime row. The first committed transition wins,
and stale later writes cannot replace the terminal outcome.

Repeating a cancellation returns the existing request or outcome. PostgreSQL does not create
duplicate terminal rows or events.

Canceling a job created by a schedule affects that occurrence only. Its definition remains enabled
until deployment synchronization changes it.
