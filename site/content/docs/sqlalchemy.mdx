---
title: SQLAlchemy
description: Join synchronous and asynchronous Psycopg transactions through SQLAlchemy's enlisted driver connection.
---

Your application already writes through SQLAlchemy. Enqueue on its enlisted Psycopg connection
so the application write and task commit together, without a second pool or transaction owner.

This is a tested recipe, not an ORM adapter package. SQLAlchemy owns transaction completion,
savepoints, and pool return. Workhorse keeps its schema lifecycle outside your ORM migrations.

## Choose the driver

For synchronous SQLAlchemy, use its Psycopg dialect with `Queue`. For asynchronous SQLAlchemy,
install `SQLAlchemy[asyncio]` and Psycopg, then use its `postgresql+psycopg` dialect with `AsyncQueue`.

The [enqueue page](/docs/enqueue#asynchronous-sqlalchemy-with-psycopg) owns the accessor,
session flush, serialized-use, lifetime, installation, and tested-version guidance.
It also links the runnable example and continuously collected integration fixture.

SQLAlchemy's asyncpg dialect is **not supported** by this recipe. Executable tests reproduce
lazy transaction startup and JSON codec incompatibilities. See the
[asyncpg boundary](/docs/enqueue#sqlalchemys-asyncpg-dialect-is-not-supported) before choosing that dialect.
Workhorse's independently owned asyncpg connections and pools remain supported.
