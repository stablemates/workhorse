This quickstart shows the main property of Workhorse: a task continues after its worker stops. In
about five minutes, you enqueue a task and run it. Then you stop the worker while a task runs, and
another run finishes the task.

Choose TypeScript, Python, Go, Rust, or Ruby for the application code. The schema installation uses
the Workhorse CLI, which runs on Node.js. Each language also needs a PostgreSQL connection string.

## 2. Install the schema

Workhorse keeps all its data in your database. The schema has tables for tasks and versioned SQL
functions for each lifecycle change. Install the schema one time with the deployment CLI of the
TypeScript package. Do this for each SDK.

A TypeScript project runs the binary that it already has as a dependency:

```bash
npm exec --no -- workhorse schema install
```

A Python, Go, Rust, or Ruby project has no `node_modules` that holds the binary. Thus, the command
gives the version. Use the same version as the SDK that you installed in step 1:

```bash
npx --package @stablemates/workhorse@0.7.1 workhorse schema install
```

This step runs on Node.js, also when the application uses Python, Go, Rust, or Ruby.
[Installation](/docs/installation) tells why the two commands are different.
[Compatibility](/docs/compatibility) gives the supported versions.

TypeScript deployment code can call the same installer directly.

```ts
import { installSchema, Pool } from "@stablemates/workhorse";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
await installSchema(pool);
```

Run this one time, as a deployment step. Runtime code must not install the schema. It calls
`assertSchemaCompatible` to check the schema.

## 3. Enqueue a task and run it

A `Queue` accepts work. A `Worker` runs the work with the handler for its task type. This example
puts the two in one file, so you can see the full lifecycle.

<Tabs items={["TypeScript", "Python", "Go", "Rust", "Ruby"]}>
  <Tab value="TypeScript">
    ```ts
    import { Admin, Pool, Queue, Worker } from "@stablemates/workhorse";

    const pool = new Pool({ connectionString: process.env.DATABASE_URL });
    const queue = new Queue(pool);
    const admin = new Admin(pool);

    const worker = new Worker(queue).handle("email.welcome", async (payload: { to: string }) => ({
      deliveredTo: payload.to,
    }));

    const taskId = await queue.enqueue("email.welcome", { to: "ada@example.com" });

    await worker.runOnce(); // one claim-and-run pass; production uses worker.run()
    console.log(await admin.getTask(taskId));
    await pool.end();
    ```

  </Tab>
  <Tab value="Python">
    ```python verify
    import os

    import psycopg
    from psycopg_pool import ConnectionPool

    from workhorse import Queue, Worker

    database_url = os.environ["DATABASE_URL"]
    with psycopg.connect(database_url) as connection:
        task_id = Queue(connection).enqueue("email.welcome", {"to": "ada@example.com"})

    with ConnectionPool(
        database_url, min_size=3, max_size=3, kwargs={"autocommit": True}
    ) as worker_pool:
        worker = Worker(worker_pool).handle(
            "email.welcome",
            lambda payload, _context: {"deliveredTo": payload["to"]},
        )
        worker.run_once()  # production uses run()
        with worker_pool.connection() as connection:
            print(
                connection.execute(
                    "SELECT state, result FROM workhorse.task_outcome WHERE task_id = %s",
                    (task_id,),
                ).fetchone()
            )
    ```

  </Tab>
  <Tab value="Go">
    ```go verify
    package main

    import (
    	"context"
    	"fmt"
    	"os"

    	"github.com/jackc/pgx/v5/pgxpool"
    	workhorse "github.com/stablemates/workhorse/go"
    )

    func main() {
    	if err := run(); err != nil {
    		panic(err)
    	}
    }

    func run() error {
    	ctx := context.Background()
    	pool, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
    	if err != nil {
    		return err
    	}
    	defer pool.Close()

    	queue := workhorse.NewQueue(workhorse.NewPGXExecutor(pool), "default")
    	taskID, err := queue.Enqueue(ctx, "email.welcome", map[string]any{
    		"to": "ada@example.com",
    	}, workhorse.EnqueueOptions{})
    	if err != nil {
    		return err
    	}

    	worker, err := workhorse.NewWorker(pool, workhorse.WorkerOptions{})
    	if err != nil {
    		return err
    	}
    	worker.Handle("email.welcome", func(
    		_ context.Context,
    		payload any,
    		_ *workhorse.HandlerContext,
    	) (any, error) {
    		message := payload.(map[string]any)
    		return map[string]any{"deliveredTo": message["to"]}, nil
    	})
    	if _, err := worker.RunOnce(ctx); err != nil { // production uses Run(ctx)
    		return err
    	}

    	var state string
    	var result []byte
    	if err := pool.QueryRow(ctx,
    		"SELECT state, result FROM workhorse.task_outcome WHERE task_id = $1",
    		taskID,
    	).Scan(&state, &result); err != nil {
    		return err
    	}
    	fmt.Println(state, string(result))
    	return nil
    }
    ```

  </Tab>
  <Tab value="Rust">
    ```rust
    use serde_json::{json, Value};
    use workhorse::deadpool_postgres::tokio_postgres::NoTls;
    use workhorse::deadpool_postgres::{Manager, Pool};
    use workhorse::{Admin, EnqueueOptions, Queue, Worker, WorkerOptions};

    #[tokio::main]
    async fn main() -> Result<(), Box<dyn std::error::Error>> {
        let url = std::env::var("DATABASE_URL")?;
        let queue = Queue::connect(&url, "default").await?;
        let enqueued = queue
            .enqueue("email.welcome", &json!({ "to": "ada@example.com" }), EnqueueOptions::default())
            .await?;

        let pool = Pool::builder(Manager::new(url.parse()?, NoTls)).max_size(4).build()?;
        let worker = Worker::new(pool, WorkerOptions::default())?;
        worker.handle("email.welcome", |payload: Value, _context| async move {
            Ok(json!({ "deliveredTo": payload["to"] }))
        });
        worker.run_once().await?; // production uses run_worker_process(&worker)

        let admin = Admin::connect(&url).await?;
        if let Some(task) = admin.get_task(enqueued.task_id).await? {
            println!("{:?} {}", task.state, task.result.unwrap_or_default());
        }
        Ok(())
    }
    ```
  </Tab>
  <Tab value="Ruby">
    ```ruby

    require "json"
    require "pg"
    require "stablemates/workhorse"

      {"deliveredTo" => payload["to"]}
    end

    puts "#{task.state} #{JSON.generate(task.result)}" if task
    ```

The worker records the state `succeeded`. Then each example reads the durable outcome. The outcome is
a record in the database, not a log line, and it stays after the process stops. The Python and Go
examples read the table `workhorse.task_outcome` directly, so the quickstart needs only one
dependency. These two languages also have `Admin` clients for the same reads. The Rust and Ruby
examples read the outcome through their `Admin` clients.

## 4. Stop the worker, and see the task finish

This step shows that a task continues after its worker stops. The handler does two parts of work.
Each part is in a named `checkpoint`. A checkpoint stores the result of its code for the task. A
later run gets the stored result and does not run the code again. The handler stops the process
between the two parts.

This example uses TypeScript, so that the two shell commands are clear. Python has the same
checkpoint as `context.checkpoint`, and Go has it as `HandlerContext.Checkpoint`. The repository has
runnable examples in `python/examples/` and `go/examples/`.

```ts title="crash-demo.ts"
import { Pool, Queue, Worker } from "@stablemates/workhorse";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
const queue = new Queue(pool);

const worker = new Worker(queue, { leaseMs: 5_000 }).handle(
  "order.fulfill",
  async (payload: { orderId: string }, ctx) => {
    const charge = await ctx.checkpoint("charge", async () => {
      console.log("charging card…"); // watch how many times this prints
      return { chargeId: `ch_${payload.orderId}` };
    });

    if (!process.env.SURVIVED) {
      console.log("simulating a crash");
      process.exit(1); // the worker dies mid-task
    }

    const label = await ctx.checkpoint("label", async () => {
      console.log("printing shipping label…");
      return { labelId: `lb_${payload.orderId}` };
    });

    return { chargeId: charge.chargeId, labelId: label.labelId };
  },
);

// The idempotency key makes the second run return the same task
// instead of enqueueing a new one.
await queue.enqueue(
  "order.fulfill",
  { orderId: "42" },
  { maxAttempts: 5, idempotency: { key: "order:42" } },
);
await worker.run();
```

Run the file two times:

```bash
node crash-demo.ts             # charges the card, then dies
SURVIVED=1 node crash-demo.ts  # finishes the task
```

**Example.** You run the two commands.

1. The first run prints `charging card…`. The `charge` checkpoint commits, and the process stops.
2. The lease of 5 s expires. A worker makes the task available again.
3. The second run enqueues with the same idempotency key, so it gets the same task.
4. The worker of the second run claims the task. The `charge` checkpoint returns its stored result,
   so `charging card…` does not print.
5. The handler prints the label and finishes the task.

The card is charged one time, also after the crash. This is the full model. After an interruption,
a handler starts again from the top. The checkpoints that you name do not run again.

## 5. Enqueue with your data

In a real application, you usually enqueue a task together with a business write. Give your open
transaction as the last argument. The task then commits or rolls back with your business write.

<Tabs items={["TypeScript", "Python", "Go", "Rust", "Ruby"]}>
  <Tab value="TypeScript">
    ```ts
    const client = await pool.connect();
    try {
      await client.query("BEGIN");
      await client.query("INSERT INTO orders (id) VALUES ($1)", [orderId]);
      await queue.enqueue("order.fulfill", { orderId }, {}, client);
      await client.query("COMMIT");
    } finally {
      client.release();
    }
    ```
  </Tab>
  <Tab value="Python">
    ```python verify
    import psycopg

    from workhorse import Queue


    def create_order(database_url: str, order_id: str) -> None:
        with psycopg.connect(database_url) as connection:
            with connection.transaction():
                connection.execute("INSERT INTO orders (id) VALUES (%s)", (order_id,))
                Queue(connection).enqueue("order.fulfill", {"orderId": order_id})
    ```

  </Tab>
  <Tab value="Go">
    ```go verify
    package transaction

    import (
    	"context"

    	"github.com/jackc/pgx/v5/pgxpool"
    	workhorse "github.com/stablemates/workhorse/go"
    )

    func createOrder(ctx context.Context, pool *pgxpool.Pool, orderID string) error {
    	tx, err := pool.Begin(ctx)
    	if err != nil {
    		return err
    	}
    	defer tx.Rollback(ctx)

    	if _, err := tx.Exec(ctx, "INSERT INTO orders (id) VALUES ($1)", orderID); err != nil {
    		return err
    	}
    	queue := workhorse.NewQueue(workhorse.NewPGXExecutor(tx), "default")
    	if _, err := queue.Enqueue(ctx, "order.fulfill", map[string]any{
    		"orderId": orderID,
    	}, workhorse.EnqueueOptions{}); err != nil {
    		return err
    	}
    	return tx.Commit(ctx)
    }
    ```

  </Tab>
  <Tab value="Rust">
    ```rust
    use serde_json::json;
    use workhorse::deadpool_postgres::Pool;
    use workhorse::{EnqueueOptions, Queue};

    pub async fn create_order(
        pool: &Pool,
        order_id: &str,
    ) -> Result<(), Box<dyn std::error::Error>> {
        let mut client = pool.get().await?;
        let transaction = client.transaction().await?;
        transaction.execute("INSERT INTO orders (id) VALUES ($1)", &[&order_id]).await?;
        Queue::new(&transaction, "default")
            .enqueue("order.fulfill", &json!({ "orderId": order_id }), EnqueueOptions::default())
            .await?;
        transaction.commit().await?;
        Ok(())
    }
    ```
  </Tab>
  <Tab value="Ruby">
    ```ruby
    def self.create_order(pool, order_id)
      pool.with do |connection|
        connection.transaction do |transaction|
          transaction.exec_params("INSERT INTO orders (id) VALUES ($1)", [order_id])
          Stablemates::Workhorse::Queue.new(transaction).enqueue("order.fulfill", {"orderId" => order_id})
        end
      end
    end
    ```
