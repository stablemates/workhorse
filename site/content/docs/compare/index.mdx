Workhorse is a durable task queue for PostgreSQL. It makes three claims. You enqueue a task inside
your own transaction. A handler that stops during a task continues after its completed checkpoints.
Workers in five languages use one SQL protocol and one dashboard. This page helps you compare
Workhorse with the products that you already know.

## Find the category of your product

The products on this page are in three categories. Each category solves a different problem, so
start with the category of the product that you use now.

- **Task queues that store work in a database.** The queue is a set of tables in a SQL database,
  often the database of the application. Workhorse is in this category. Most products in it can
  enqueue a task in the application's transaction.
- **Task queues on Redis or a message broker.** The queue is in Redis or in a broker such as
  RabbitMQ. The broker is a second service beside the application database. A task cannot commit
  in the same transaction as the application data.
- **Workflow platforms.** These platforms run multi-step workflows and record each completed step.
  Most of them need their own server or a cloud service. Workhorse is a task queue, not a workflow
  platform. It has checkpoints, durable waits, and child tasks, but no workflow runtime.

## How this page stays correct

Each fact comes from the documentation or the source code of the product, at the version in the
table. The facts give no performance numbers. A person checks each product page every quarter
against the newest release, then changes the version and the date. If you find a fact that is not
correct, open an issue in the [Workhorse repository](https://github.com/stablemates/workhorse).
